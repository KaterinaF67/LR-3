# ЛР №3 — Методы оптимизации, вариант 19

**Федоровская Е. С., Б24-517**

## Задача

Назначение серверов на задачи с ограничением числа включённых серверов. Базовый экземпляр: 8 серверов, 15 задач, максимум 5 включённых серверов.

## Что реализовано

- вариант `V=19`, seed `10125`;
- MILP с бинарными `x[i,j]` и `y[i]`;
- LP-релаксация и интегральный зазор;
- HiGHS через `scipy.optimize.milp`, presolve;
- независимая NumPy-проверка решения из CSV;
- базовый, дефицитный и стрессовый сценарии;
- изменение набора включённых серверов в сценариях;
- эксперимент масштабирования 10 / 20 / 40 задач;
- жадная эвристика и зазор к MILP;
- эксперимент с tight big-M и завышенным M;
- дополнительное задание: две эквивалентные формулировки и сравнение силы LP-релаксаций;
- полные диагностические логи HiGHS базового MILP, обеих MILP-формулировок и обеих LP-релаксаций;
- независимая проверка усиленной MILP, включая индивидуальные связи `x[i,j] <= y[i]`;
- расширение по пункту 6 списка «со звёздочкой»: сравнение двух формулировок, LP-оценок, времени и ветвления с логами;
- CSV, JSON, графики и отчёт.

## Генерация данных

Генератор NumPy `default_rng(seed=10125)` создаёт 8 серверов и 15 задач. Диапазоны параметров исходного экземпляра:

- CPU-потребность задачи: целые 2–6 усл. CPU, RAM: 3–10 ГБ;
- CPU-ёмкость сервера: целые 14–21 усл. CPU, RAM: 24–38 ГБ;
- фиксированная стоимость сервера: равномерно из `[22,45)`, стоимость назначения пары: из `[3,15)` (округление до 0.01 усл. ед.);
- одновременно можно включить не больше 5 серверов.

Файлы `servers.csv`, `tasks.csv`, `assignment_cost.csv` и `metadata.json` записываются в `data/`, затем модель загружает их с диска. Для масштабирования меняются числа задач/серверов, seed задаётся как `10125 + n_tasks`.

## Жадная эвристика

Она проверяет **три порядка задач**: по убыванию нормированной суммарной CPU/RAM-потребности, по CPU и по RAM. Для каждого порядка последовательно выбирает допустимый сервер с минимальной добавочной стоимостью (включая разовую стоимость активации нового сервера), затем выбирает самый дешёвый из полностью допустимых планов. Результат не имеет гарантии глобального оптимума.

## Установка и запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

`main.py` заново создаёт данные из seed, решает все эксперименты, проверяет решения. Время выполнения экспериментальных задач может немного различаться между компьютерами и запусками. PDF в архиве собран по сохранённым CSV одного запуска.


## Структура

```text
data/                 входные CSV и metadata.json
src/data.py           генерация и загрузка данных
src/model.py          LP/MILP, big-M, две формулировки

results/              решения, сценарии, проверки, логи, графики
main.py               полный воспроизводимый запуск
```

## Интерпретация big-M

Связка `sum_j x[i,j] <= M[i] * y[i]` запрещает назначения на выключенный сервер. `M[i]` выбирается не произвольно, а как верхняя граница числа задач, которые могут физически поместиться на сервере по CPU и RAM. Отдельный эксперимент показывает, как завышенное `M` ослабляет LP-релаксацию.

## Логи формулировок для дополнительного задания и звёздочки № 6

В `results/` сохраняются файлы `solver_formulation_aggregate_milp_full.log`, `solver_formulation_disaggregated_milp_full.log`, а также `solver_formulation_aggregate_lp_full.log` и `solver_formulation_disaggregated_lp_full.log`. Результаты сравнения в `formulation_comparison.csv`, независимая проверка усиленной модели в `verification_disaggregated.json`. У агрегированной и усиленной формулировки совпадает целочисленный оптимум; для обоих MILP-сравнений задан `mip_rel_gap=1e-7` (в логах финальный gap равен 0). LP-релаксация усиленной формулировки сильнее.
